# Security Findings and Fixes

This document records the findings addressed during the Modal migration. An
invariant is the security or data-integrity condition that must remain true even
when the gateway is reachable from the public internet or scales on Modal.

| # | Finding | Broken invariant | Fix |
|---|---|---|---|
| 1 | Production documentation and gateway exposure | Production metadata and gateway routes must not be anonymously reachable. | Production disables `/docs`, `/redoc`, and `/openapi.json`. The Modal ASGI endpoint also requires Modal proxy authentication, while application routes enforce the installation bearer token. |
| 2 | Config disclosure (`/v1/status`, `/v1/providers`, `/v1/capabilities`) | Provider order, model selection, capabilities, and rate limits are tenant configuration and require authentication. | All configuration-bearing read routes call the shared installation-token validator before returning data. |
| 3 | Unauthenticated LLM abuse (`/v1/chat`) | No unauthenticated caller may execute or bill the data plane. | `/v1/chat` and the related chat, embedding, batch, and media routes require `Authorization: Bearer <install_token>` and reject a missing credential with HTTP 401. |
| 4 | SSRF through the image URL resolver | Server-side fetches may reach only explicitly approved public destinations, including after redirects and DNS resolution. | Image hosts must match `GLC_IMAGE_URL_ALLOWLIST`. The resolver permits only HTTP(S) on ports 80/443, rejects URL credentials, resolves and rejects every non-global IPv4 or IPv6 address, disables automatic redirects, and repeats the complete validation before every redirect hop. |
| 5 | Verbose upstream errors | Provider names, endpoints, credentials-related responses, and raw upstream bodies must remain in server-side diagnostics. | Provider failures are logged server-side and converted to generic client messages such as `upstream provider request failed` or `upstream service unavailable`. Image-fetch failures are handled the same way. |
| 6 | Unauthenticated usage and cost reads (`/v1/cost/by_agent`, `/v1/calls`) | Usage records belong to an authenticated tenant and must not be readable across tenant boundaries. | Both endpoints require the installation token. Ledger rows carry a stable tenant identifier derived from the token, and queries filter by that authenticated tenant before returning results. |
| 7 | Single function with no egress wall (A3) | Untrusted commands must not inherit unrestricted network access from the gateway process. | Untrusted commands run in short-lived Modal Sandboxes with bounded time, CPU, memory, output, and an explicit `outbound_domain_allowlist`. |
| 8 | Leak 1: shared process environment / one secret for the whole function (A4) | Adapter code must not be able to read another provider's credential from its process environment; a component may receive only the credential needed for its current operation. | Each credential-bearing provider adapter runs in its own Modal function with one provider-specific secret. The gateway and its channel-adapter stubs hold no provider secrets, so an environment read there cannot expose a provider key. Tool credentials are issued only to the selected short-lived Sandbox slot. |
| 9 | Leak 2: writable audit log | Adapter and provider code must not be able to erase or silently rewrite audit history, and persisted tampering must be detectable. | Only the gateway mounts the audit volume. SQLite triggers reject `UPDATE` and `DELETE`; every entry contains the previous entry's SHA-256 digest and its own digest; appends serialize under an immediate transaction; startup verifies the complete chain and refuses a modified store. |
| 10 | Leak 3: pairing escalation | Untrusted tool and provider code must not be able to import a privileged pairing API and modify the gateway's real trust store. | The pairing volume is mounted only inside the gateway function. Provider functions receive no pairing volume, and untrusted tools run in a minimal Sandbox image containing neither the `glc` package nor the pairing volume; therefore `force_pair_owner()` cannot alter gateway pairing state outside the trusted gateway process. |
| 11 | Leak 4: readable install token | The production control credential must exist only in the trusted gateway's process environment and must never be persisted on the shared data volume. | Production requires `GLC_INSTALL_TOKEN` from the gateway-only `glc-gateway-auth` Modal Secret and fails closed when it is absent or empty. Provider functions and tool Sandboxes do not receive the Secret. Gateway startup removes the legacy `/data/glc/install_token` file; development retains its local file fallback. |
| 12 | Leak 5: policy engine monkey-patch | Untrusted caller code must not share the process that makes authoritative policy decisions, and a policy-service failure must never become an allow decision. | Modal production routes policy evaluation to a dedicated secretless `policy_evaluator` function. It mounts only the separate `glc-policy` volume, reloads that volume before evaluation, and returns a serialized verdict. The gateway proxy denies when remote evaluation fails; local development retains the in-process engine. |
| 13 | Leak 6: unbounded egress | Untrusted adapter or tool code must not execute in the gateway Function or receive unrestricted outbound networking. | Untrusted commands run in short-lived Modal Sandboxes. With no approved domains the Sandbox uses `block_network=True`; otherwise it receives the explicit domain allowlist. It also has bounded resources and output and at most one selected tool Secret. Channel adapters connect through the authenticated gateway boundary rather than executing inside it. Allowed destinations remain an intentional residual exfiltration channel and must be kept minimal. |
| 14 | Leak 7: subprocess and shell | Untrusted subprocesses must not run as root, regain privilege, modify shared storage, or escape the runtime's syscall boundary. | The Sandbox-only image contains a small launcher that sets Linux `no_new_privs`, removes supplementary groups, irreversibly drops to UID/GID 65532, and executes in `/tmp` with a restrictive umask. No Volume is mounted, system image paths remain root-owned, each Sandbox is short-lived and resource-bounded, and Modal's default gVisor Sandbox supplies the platform syscall boundary. Modal does not expose documented root-filesystem-read-only or custom seccomp controls, so no unsupported enforcement is claimed. |
| 15 | Leak 8: kill the gateway | Untrusted adapter, provider, policy, or tool code must not share the gateway's PID namespace or be able to signal its process. | Tool commands run in separate Modal Sandbox containers; provider and policy execution run in separate Modal Functions; channel adapters connect through the authenticated network boundary. A signal sent by any of those workloads can terminate only its own isolated container, not the gateway process. |
| 16 | Leak 9: cross-channel envelope spoof | A channel identity established by the authenticated WebSocket route must not be overridden by caller-controlled envelope data. | Immediately after envelope validation, the gateway compares `env.channel` with the `{name}` route segment. A mismatch is audited under the trusted route channel, closed with WebSocket code 1008, and processing stops. All downstream checks, audit writes, rate limiting, and replies use the route name. |
| 17 | Leak 10: cost-ledger poisoning | Usage and cost calculations must accept only plausible records authenticated by the gateway writer, never arbitrary rows inserted by another process or direct SQL. | Production requires a gateway-only `GLC_LEDGER_SIGNING_KEY`. `log_call()` validates identity fields and bounded non-negative counters, binds the authenticated tenant, and HMAC-SHA256 signs all 24 ledger fields. Every recent, aggregate, and per-agent query verifies signatures in constant time and excludes unsigned, modified, or forged rows. Provider functions and tool Sandboxes do not receive the signing key or ledger volume. |
| 18 | Non-reproducible image (A5) | A deployment must resolve to the reviewed base image and dependency graph, not newer packages selected at build time. | The Debian/Python base image is pinned by digest. Modal installs from `uv.lock` with frozen resolution, a pinned uv version, and development dependencies excluded. |
| 19 | Audit volume assumes one writer (A6) | SQLite audit, pairing, and usage files on a Modal Volume must never have multiple container writers, and acknowledged writes must be persisted. | The gateway function is capped at `max_containers=1`. Its ASGI wrapper explicitly commits the Modal Volume before final HTTP responses, WebSocket replies or closure, and lifespan shutdown completion. |

## Deployment note

The fixes are present in the workspace. The latest live deployment is pending
creation of the provider-scoped `glc-provider-gemini` and gateway-only
`glc-gateway-auth` secrets in Modal's `main` environment; the deployment
intentionally does not fall back to persisted or whole-function secrets. The
gateway secret must define both `GLC_INSTALL_TOKEN` and `GLC_LEDGER_SIGNING_KEY`.
